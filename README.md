# 梁选 · DSH 插件

TypeScript / React 插件，在任意模式的任务运行期间展示梁文锋语录与明确标注的观点整理。

输入框底部、访问模式右侧提供独立的 **梁选** 开关，文字在开关右侧。首次安装默认开启，开关状态保存在当前浏览器中，刷新与重启后保留，并同步到同源标签页。开关适用于所有 Agent 模式，不注册独立 preset，也不改变模型或系统提示词。

插件订阅当前主会话的真实运行状态：任务开始展示，运行期间按原规则轮播，结束时收起。关闭开关会立即停止弹窗及音效；切换页面、进入后台或等待权限确认/用户回答时暂时隐藏。后台任务不会遮挡当前会话。开发构建额外包含 **190 条文选库和模拟预览面板**（181 条原汇编节选、1 条用户补充节选、8 条观点整理）；模拟操作不会发送模型请求。

## 安装与使用

当前准备版本为 `0.1.2`，是否已发布以 npm / GitHub Release 为准。已适配 DeepSeek Harness `0.2.1-rc.3` Web。取得发行包后，在包所在目录运行：

```powershell
dsh plugin --profile web add ./dsh-liang-says-0.1.2.tgz
```

安装后重启对应的 DSH Web profile。输入框底部的“梁选”开关默认开启，开始任务即可展示。开关关闭后不再展示，也不播放音效。正式包仅包含真实会话功能；侧栏“梁选预览”仅供开发构建使用。

输入面板及其附件、权限、模型选择菜单位于梁选弹窗上方，可以随时输入和操作。聚焦、输入、清空或失焦都不会暂停弹窗和音效。输入框及菜单优先处理自己的 Esc 按键；点击文案区域或收起按钮仍可关闭当前弹窗。

也可在 DSH「添加插件」中填写已发布的 npm 包名 `dsh-liang-says`，或填写 Git 仓库地址 `https://github.com/cct124/dsh-liang-says`。Git 直装需要包含本次结构调整的提交；旧的 `v0.1.0` 源码标签仍不支持直装。Git 安装时包管理器先安装构建依赖，再运行 `prepare` 生成正式运行文件；若 DSH / pnpm 提示审批 Git 构建脚本，检查来源后允许该仓库的构建并重试。需要 Node.js >= 24.9 和可访问依赖注册表的网络。

从本地仓库根目录安装时，先执行 `npm ci`（自动运行 prepare），再使用 `dsh plugin --profile web add "link:<仓库绝对路径>"`。使用 `npm ci --ignore-scripts` 时需另行执行 `npm run build`。

如果同一 profile 安装过 `dsh-liang-says-dev`，先用 `dsh plugin --profile web remove dsh-liang-says-dev` 移除开发包，再安装正式包，避免重复挂载。卸载正式包使用 `dsh plugin --profile web remove dsh-liang-says`，随后重启该 profile。

## 本地开发

需要 Node.js >= 24.9，以及已安装依赖、完成构建的 DeepSeek Harness 源码。本次适配版本为 `0.2.1-rc.3`。源码默认位于本项目的同级 `deepseek-harness`，可通过 `DSH_SOURCE` 指定其他位置。

```powershell
npm ci --ignore-scripts
npm run build:dev
npm run dsh:install
npm run dsh:start
```

启动后打开终端给出的登录链接，完成本地认证后访问 http://127.0.0.1:41831，在 DSH 侧栏选择“梁选预览”（英文界面为 Liang preview；未固定时在“更多”中）。数据保存在项目内 `.dsh-dev/`，不会安装到日常使用的 Web 或 Desktop profile。端口可用 `LIANG_PORT` 修改。

另开终端执行 `npm run dev` 监听插件源码，生成 `dist/dev/client.js`。DSH 的客户端 HMR 在启用时可接收重建；若未自动更新，刷新测试页面。宿主入口或清单变化后重新运行安装命令并重启测试宿主。

如果源码宿主缺少运行产物，在 Harness 源码目录按该版本的开发说明先执行 `pnpm install --frozen-lockfile` 和 `pnpm run build:artifacts`。宿主脚本与插件脚本各自负责自己的构建。

## 预览功能

- 模拟深度思考、工具执行、回答与任务结束，状态仅在客户端内存中。
- 任务开始时展示第一条；思考、工具执行和输出回答均持续轮播，任务结束时收起。
- 每次展示独立抽取 20～45 秒停留时长，经典分越高通常越久；1× / 5× / 10× 时间倍率。
- 停留时间从正文和落款完成入场后开始，不计入散开与聚拢的动画时间。
- 立即展示、下一句、最短 / 最长文案，以及语录库中的指定文案。
- 点击弹层任意位置或 Esc 关闭；任务仍运行时，等待本条设定的完整时长再弹出下一条。
- 思考、工具、回答之间切换不会重置计时或换句；结束、离开页面清理本轮计时。
- 后台页面暂停，不补弹；减少动态效果模式保留淡入淡出。
- 语录库展示经典分、当前出现分和下一次抽中概率；操控面板展示本次停留时长和倒计时。

真实会话通过 `conversation.input.left` 挂载开关，通过 `shell.overlay` 管理弹窗生命周期，并订阅 `useSessions`、`useSessionStatus`、`usePanelInfo` 标准状态。弹窗通过 React portal 渲染到 `main.conversation` 内，只覆盖会话面板，层级低于原生输入面板及其菜单；不搬动或重新创建宿主编辑器。侧栏展开、收起、拖动宽度或窗口缩放时跟随布局，不覆盖左侧导航、右侧文件面板与窗口顶栏。原生预览通过 `main` 与 `sidebar.panellist` 挂载，复用相同的开关偏好、`QuoteOverlay` 与抽选逻辑；底部操控区仅在开发构建中存在。

视觉参数：黑色底层不透明度 60%（40% 透明）；光芒单独保持 50% 不透明度，深浅色模式的人像均为 85% 不透明，无底部渐隐，父层不再降低人像透明度；文字保持不透明。背景入场约 600ms。正文与落款共享同一批粒子入场：风从左侧带入文字附近的细粒子，每个粒子按独立的时间和速度渐显，顺风向右移动并轻微上下翻卷，随后减速落到对应笔画上；文字由左向右逐渐成形，约 2.4 秒后衔接清晰的正文，与出场向右吹散的风向一致。深色模式粒子在暖白、浅金、淡灰金之间随机取细微色差，颜色在单次动画内保持稳定；全部粒子落定后，在隔离的文字层内以 plus-lighter 合成方式交接给正文，避免普通透明度交叉淡化造成中途变暗，同时恢复正文原色。落款“—— 梁文锋”位于文案段落右下角，右侧对齐正文排版后的实际右边缘（多行时取各行最右侧），切换文案和调整窗口尺寸时自动更新，距正文下方 22px（紧凑布局为 12px）。

出场模拟从左向右吹的风：左侧笔画先碎开，侵蚀边界逐渐向右推进，正文与落款化作细灰，顺风向右飘移并伴随少量上下翻卷，约 1.5 秒消失。换句时保留人像和光芒，点击收起也使用同样的消散效果。Canvas 按实际排版位置采样笔画，最多 6500 个粒子；长文案自动调整采样粒度，动画结束后移除画布。取消时清理动画帧和计时器，帧调度暂停时有完成兜底；窗口尺寸改变时直接回到当前布局的最终状态。减少动态效果时改用淡入淡出。

文案聚拢完成后，间歇性的轻风从左向右掠过正文与署名。每次按实际换行识别独立飘带，行内各字从本行左端依次轻轻抬起、回落；各行分别随机调整启动时间、传播速度、力度及抬起/回落的波形，保持同一阵风的方向，同时避免多行轨迹完全一致。署名单独成行，窗口变化后按新布局重新分组。每阵风结束后静置 4～8.5 秒；单字上下位移不超过约 3.3px，不改变字号、透明度和换行。切换与收起时冻结当前单字位置，并由实际排版位置采样出场粒子，避免先回弹。开启减少动态效果或页面隐藏时停用轻风，关闭弹窗或卸载时清理动画与计时器。

随机停留时长按整秒计算：`round(20 + 15 × (classicScore - 1) / 99 + 10 × U)`，其中 `U` 为每次重新抽取的 0～1 均匀随机数。整个范围为 20～45 秒，例如经典分 50 约为 27～37 秒，经典分 100 约为 35～45 秒；高分提高基础时长，同时保留随机浮动。时长只在选中一条文案时计算一次，状态切换或界面重绘不会重新抽取。

背景层次从后向前为光芒、人像；文案与粒子位于其上方。光效层以人像 PNG 的透明轮廓做减法裁切，人物与裁切使用同一组静态尺寸和位置变量；两者先合成，再由共同父层进行一次呼吸缩放，光芒也随整组轻微缩放。裁切不再独立动画，避免边缘因两种插值和取整方式出现闪动，保持人物轮廓清晰；不额外叠加遮光层。深浅色模式的人像不透明度均为 85%，光芒透明度独立控制。

弹窗跟随 DSH 当前主题：深色模式使用原有黑色半透明底层（60% 不透明度）；浅色模式底层为 `rgb(207 138 0 / 0%)`，完全透明。浅色正文与署名使用 `#ffdf89`，正文阴影为 `0 0px 0px #00000069, 0 1px 3px #000000f2`，署名阴影为 `0 1px 1px #000000b8`。浅色模式粒子从五种带细微色差的暖金棕色起步，按各自聚拢进度逐渐变成正文金色，在落到笔画位置时完成变色，再交接给正文；出场时先保持正文金色，随风吹散后逐渐转回暖金棕色。粒子画布从出现起即带实时轮廓阴影，随粒子聚拢逐渐形成文字阴影，避免成字后才出现阴影。装饰与收起提示保留原有配色。

入场音效使用 `asset/sfx/06-cinematic-riser-full.mp3`（约 3 秒），播放音量设为 25%，比正文与署名粒子进场提前 0.3 秒从头播放一次，保留自然尾音。换句、收起、重置或卸载时停止并复位，并取消尚未开始的粒子入场，避免重叠；浏览器拒绝播放或音频加载失败时仍正常完成视觉动画。MP3 作为 data URL 随客户端构建内嵌，无需额外的远程音频请求。

## 数据

`asset/quotes/quotes.json` 是运行时数据，数组每项严格只有 `id`、`text`、`classicScore`。ID 根据规范化展示文本生成，调整顺序不改变 ID。正文发生校订或合并时生成新 ID，原条目 ID 保存在来源记录中。

原始 `asset/quotes/liang-wenfeng-public-statements.md` 完整保留。2026-10-28 根据[每日经济新闻报道](https://www.nbd.com.cn/articles/2026-07-23/4504599.html)审查后，以 `asset/quotes/editorial-review.json` 保存校订、合并、语境补充、暂缓展示及新增观点整理。23 组合并使用省略号标识摘录之间的间隔，不声称它们是连续逐字稿；3 条直接校订；2 条因指代或比较条件不完整退出轮播。8 条新增概述明确标注“观点整理，非逐字引语”。

`asset/quotes/quote-sources.json` 保存原文行号、旧 ID、校订理由、来源章节及核对状态。只给报道可对应的内容标 S13；supported 表示内容可对应，**不表示逐字认证**。未被该报道收录的内容沿用原汇编其他来源，不判为错误；2019—2024 年内容只做本地语境整理，没有借此宣称完成外部核验。B/C 仍是流出实录的媒体整理，非官方授权讲话。报道确认的会议月份为 2026 年 5 月，发布日期为 7 月 23 日，不据此确认具体会议日。

`asset/quotes/quote-context.json` 保存年份、话题和文本性质。弹窗落款统一只显示“——梁文锋”，不附加括号或下方说明；观点整理、年份、语境与来源信息保留在语录库和开发面板中。

用户追加的原文及经典分保存在 `asset/quotes/editorial-review.json` 的 `userQuotes` 中，并随生成流程加入运行时数据；未提供出处与讲话日期时，单独标为用户补充，不自动沿用原汇编的媒体来源或年份。

经典分是编辑权重，不是可靠性评分：代表性金句通常 85–100，普通独立陈述以 50–70 为基础，强依赖上下文的片段降至 35–40。具体人工调整在 `scripts/structure-quotes.mjs` 中，可重新生成与复核：

```powershell
npm run quotes
npm run quotes:check
```

抽选权重为 `classicScore / (1 + 出现分)`。上一条在多条语录时不参与下一次抽取。每次真正开始展示后，所有出现分减一（最低零），选中项加六。选择但被取消不计分；同一展示只提交一次。分数只在客户端内存中，重载清零。

## 构建与分发

- `npm run build:dev` → `dist/dev/`，包名 `dsh-liang-says-dev`，含开发预览面板。
- `npm run build` → `dist/release/`，包名 `dsh-liang-says`，包含真实会话开关与弹层，不含开发模拟器入口。
- `npm run pack:dev` → 本地测试用 `.tgz`。不要对仓库根目录直接执行发布；应发布经过检查的正式输出目录。
- `npm run release:prepare` → 校验语录、类型和测试，构建正式包，检查实际客户端注册与包内文件，然后生成 `dist/dsh-liang-says-0.1.2.tgz`、`dist/SHA256SUMS` 和 `dist/release-info.json`。

交付格式是 DSH 原生 npm bundle：宿主入口、客户端 JavaScript、运行时数据、locale、图标与 `cordis.patch.yml`，附带 README、更新记录、MIT 许可证和音效来源说明。仓库根目录及开发包保留 `private: true`，仅正式输出清单允许发布。仓库通过根清单的 `exports` 和 `dsh.bundle.patch` 指向 `dist/release`，Git 安装的 prepare 生成这些文件，Git 打包仅包含正式输出。发行工作流仍使用检查过的独立 `.tgz`，无需在 Git 中提交生成文件。

Git 安装回归验证可运行 `pnpm --config.verify-deps-before-run=false run check:git-install`。脚本在 `.dev-logs/` 内创建一次性源码仓库和安装目录，验证无构建产物的 Git 安装、入口、组合包补丁和静态资源；不会提交到当前仓库、推送或发布。`verify-deps-before-run=false` 用于保留当前项目由 npm lockfile 安装的依赖，不影响隔离目录的正常依赖安装。

GitHub Actions 分两条流程：PR 合并到 `main` 后自动检查并将测试用 `.tgz` 保存到 Actions Artifacts；推送 `v*` 版本标签后，校验标签、版本号和 main 提交关系，构建一次，再把同一份 `.tgz` 发布到 npm 和 GitHub Release。正式发布使用 npm Trusted Publishing（OIDC）；已有版本先核对完整性，部分完成的 GitHub Release 草稿可以续跑。普通分支推送和未合并的 PR 不执行打包，合并 main 不自动发布正式版本。

本地 `release:prepare` 只做检查和打包。首次 npm 包初始化、可信发布设置及日常发版操作见 [RELEASING.md](https://github.com/cct124/dsh-liang-says/blob/main/RELEASING.md)，版本内容见 [CHANGELOG.md](https://github.com/cct124/dsh-liang-says/blob/main/CHANGELOG.md)。

React 与 ReactDOM 由 DSH 浏览器模块表提供，未打包第二份运行时。构建用 esbuild 将 TS/TSX 编译为 DSH 的 `window.__ModuleLoader__.load` 格式。图片直接包含在客户端资源内，预览不依赖外部图片或 CDN。

```powershell
npm test
npm run typecheck
```

测试覆盖抽选、冷却衰减、各运行阶段连续计时、随机时长范围及分数偏置、入场计时边界、隐藏页面、连续去重、取消竞态、粒子颜色交接、独立行飘动和语录校订。打包时另行检查正式客户端入口注册、React 外置、资源内嵌、开发面板排除及发布文件清单。

测试宿主为 `0.2.1-rc.3` 源码 Web 实例；原生 Desktop 与其他宿主版本尚未验证。
